# บทที่ 4
# การทดลองและผลการดำเนินงาน (ผลการพัฒนาและทดสอบระบบ)

ในบทนี้จะนำเสนอผลการดำเนินงานของระบบคลังผลงานโครงงานและรายวิชา กรณีศึกษาสาขาวิศวกรรมคอมพิวเตอร์ มหาวิทยาลัยพะเยา โดยแบ่งออกเป็น 4 ส่วนหลัก ได้แก่ ผลการพัฒนาระบบ ผลการทดสอบการทำงานของระบบ การวิเคราะห์และอภิปรายผลการทดลอง และบทสรุปของบท ซึ่งรายละเอียดของบทสามารถแสดงและอธิบายได้ดังต่อไปนี้

---

## 4.1 ผลการพัฒนาระบบ (System Implementation Results)

ส่วนต่อประสานกับผู้ใช้ของระบบคลังผลงานโครงงานและรายวิชา ถูกพัฒนาขึ้นด้วย React 19 และ TypeScript ร่วมกับ Vite โดยมีการเชื่อมต่อข้อมูลกับบริการ Backend API (Node.js + Express) ผ่านสถาปัตยกรรม RESTful API การจัดวางเลย์เอาต์และการแสดงผลได้รับการออกแบบตามแนวคิด Responsive Web Design ให้รองรับการเข้าถึงได้จากทุกอุปกรณ์ ทั้งคอมพิวเตอร์ตั้งโต๊ะ โน้ตบุ๊ก แท็บเล็ต และสมาร์ตโฟน

ในการนำเสนอผลการพัฒนาระบบ ได้จัดลำดับการทำงานและภาพหน้าจอตามลำดับการเข้าใช้งานจริงของผู้ใช้ระบบ (User Journey & Application Flow) ซึ่งแบ่งออกเป็น 2 ส่วนหลัก ได้แก่ **ส่วนของผู้ใช้งานระบบ** (ครอบคลุมตั้งแต่ผู้ใช้งานทั่วไปที่ยังไม่ล็อกอิน, นิสิต, และอาจารย์ผู้สอน) และ **ส่วนของผู้ดูแลระบบ** โดยมีรายละเอียดดังต่อไปนี้

---

### 4.1.1 ส่วนของผู้ใช้งานระบบ (User Interface for System Users)

ส่วนนี้แสดงหน้าจอและขั้นตอนการใช้งานสำหรับบุคคลทั่วไปและผู้ใช้งานระบบ โดยเรียงลำดับตามขั้นตอนการเข้าใช้งานจริงของระบบ ตั้งแต่การเปิดหน้าแรกเพื่อสืบค้นผลงาน การดูรายละเอียดรายวิชา การดูรายละเอียดผลงาน การเข้าสู่ระบบ และการลงทะเบียนสมาชิก ดังนี้:

#### 4.1.1.1 หน้าแรกของระบบและศูนย์รวมสืบค้นแคตตาล็อกผลงานสำหรับบุคคลทั่วไป (Home Page - Public View)

เมื่อผู้ใช้งานเปิดเข้าสู่ระบบผ่าน URL หลัก (`/`) หน้าจอแรกที่ระบบแสดงผลคือหน้าแคตตาล็อกรวมรายวิชาและผลงานโครงงาน ซึ่งเปิดให้บุคคลทั่วไปสามารถเข้าถึงและค้นหาข้อมูลได้แบบสาธารณะโดยไม่ต้องเข้าสู่ระบบ

*(ภาพที่ 4.1 แสดงหน้าแรกของระบบและศูนย์รวมสืบค้นแคตตาล็อกผลงานสำหรับบุคคลทั่วไป)*

จากภาพที่ 4.1 สามารถอธิบายส่วนประกอบของหน้าจอได้ดังนี้

1. **ปุ่มเข้าสู่ระบบ:** ปุ่มที่มุมบนขวาของหน้าจอ สำหรับนำทางผู้ใช้ไปยังหน้าเข้าสู่ระบบ เพื่อยืนยันตัวตนเข้าใช้งานฟังก์ชันและสิทธิ์ขั้นสูง
2. **ส่วนแสดงสัญลักษณ์และชื่อระบบ:** แสดงตราสัญลักษณ์ UP พร้อมชื่อ "มหาวิทยาลัยพะเยา Classroom Hub" บนแถบเมนูด้านข้าง โดยผู้ใช้สามารถคลิกเพื่อย่อหรือขยายแถบเมนูนำทางได้
3. **ช่องค้นหาอัจฉริยะ (Smart Search Box):** ช่องสำหรับระบุคำค้นหาแบบหลายเงื่อนไข "ค้นหารายวิชา / ชื่อผลงาน / แท็ก / ปี พ.ศ..." พร้อมระบบหน่วงเวลา (Debounce) เพื่อค้นหาข้อมูลแบบเรียลไทม์
4. **แท็บสลับมุมมองการกรองข้อมูล (Catalog Filter Tabs):** แถบปุ่มสำหรับเลือกกรองประเภทข้อมูลที่ต้องการแสดงผล ได้แก่ "ทั้งหมด (25)", "รายวิชา (13)" และ "ผลงานที่มีผู้เข้าชมเยอะที่สุด (12)" พร้อมแสดงจำนวนรายการของแต่ละประเภท
5. **การ์ดแสดงผลงานยอดนิยม (Popular Assignment Card):** การ์ดแสดงผลงานที่มีผู้เข้าชมสูงสุด ประกอบด้วย ป้ายประเภทผลงาน (Web Application), ป้ายลำดับความนิยม (อันดับ 1), ป้ายรหัสวิชา (COM059), ป้ายปี พ.ศ. (พ.ศ. 2569), ชื่อผลงาน (ระบบจองห้องประชุมออนไลน์), ชื่อรายวิชา (วิศวกรรมซอฟต์แวร์), รายละเอียดโดยย่อของผลงาน และชื่อเจ้าของผลงาน (THIRAPAT WANGKEEREE)

---

#### 4.1.1.2 หน้ารายละเอียดรายวิชาและคลังผลงานในวิชาสำหรับบุคคลทั่วไป (Class Detail Page - Public View)

เมื่อผู้ใช้คลิกเลือกรายวิชาจากหน้าแรก ระบบจะนำทางมายังหน้ารายละเอียดรายวิชา (`/class/:class_id`) เพื่อแสดงข้อมูลภาพรวมของวิชาและรายการผลงานโครงงานทั้งหมดที่จัดเก็บอยู่ในรายวิชานั้น

*(ภาพที่ 4.2 แสดงหน้ารายละเอียดรายวิชาและคลังผลงานในวิชาสำหรับบุคคลทั่วไป)*

จากภาพที่ 4.2 สามารถอธิบายส่วนประกอบของหน้าจอได้ดังนี้

1. **ปุ่มเข้าสู่ระบบ:** ปุ่มที่มุมบนขวาสำหรับนำทางผู้ใช้ที่ยังไม่ได้เข้าสู่ระบบไปยังหน้าเข้าสู่ระบบ เพื่อให้สามารถเข้าถึงทรัพยากร ไฟล์แนบ ลิงก์ผลงาน และร่วมแสดงความคิดเห็นได้
2. **ส่วนแสดงสัญลักษณ์และชื่อระบบ:** แสดงชื่อ "มหาวิทยาลัยพะเยา Classroom Hub" บนแถบเมนูด้านข้าง
3. **ปุ่มกลับสู่หน้าหลัก:** ปุ่มนำทางย้อนกลับไปยังหน้าแรกของระบบ (Home)
4. **ส่วนข้อมูลรายวิชา:** แสดงข้อมูลสำคัญของรายวิชา ประกอบด้วย ป้ายรหัสรายวิชา (NW05), ป้ายปี พ.ศ. ที่เปิดรายวิชา (พ.ศ. 2569), ชื่อรายวิชาภาษาไทยและภาษาอังกฤษ "เครือข่ายคอมพิวเตอร์ (Computer Networks)" และกล่องแสดงคำอธิบายรายวิชา
5. **รายการผลงานในรายวิชา:** แสดงการ์ดผลงานโครงงานทั้งหมดที่จัดเก็บอยู่ในรายวิชานี้ โดยแต่ละการ์ดระบุประเภทผลงาน, ป้ายปี พ.ศ. ที่จัดทำ, ชื่อผลงาน (เช่น test 0099, วิเคราะห์แพ็กเก็ตด้วย Wireshark), วันที่อัปเดตล่าสุด, จำนวนครั้งที่เข้าชม และปุ่ม "เข้าชม ->" สำหรับเปิดดูรายละเอียดผลงาน

---

#### 4.1.1.3 หน้ารายละเอียดผลงานสำหรับบุคคลทั่วไป (Assignment Detail Page - Public View)

เมื่อผู้ใช้ทั่วไปคลิกเปิดดูผลงานโครงงาน ระบบจะนำทางมายังหน้ารายละเอียดผลงาน (`/assignment/:id`) ในมุมมองสำหรับบุคคลทั่วไป โดยจะแสดงเฉพาะข้อมูลเบื้องต้นและปิดกั้นการเข้าถึงไฟล์เอกสารโครงงาน เพื่อความปลอดภัยตามนโยบายการควบคุมสิทธิ์

*(ภาพที่ 4.3 แสดงหน้ารายละเอียดผลงานสำหรับบุคคลทั่วไป)*

จากภาพที่ 4.3 สามารถอธิบายส่วนประกอบของหน้าจอได้ดังนี้

1. **ปุ่มเข้าสู่ระบบ:** ปุ่มนำทางไปยังหน้าเข้าสู่ระบบสำหรับผู้ใช้ทั่วไปที่ต้องการเข้าถึงฟังก์ชันและทรัพยากรเพิ่มเติม
2. **ส่วนแสดงสัญลักษณ์และชื่อระบบ:** แสดงชื่อ "มหาวิทยาลัยพะเยา Classroom Hub" บนแถบเมนูด้านข้าง
3. **ปุ่มย้อนกลับ:** ปุ่มสำหรับนำทางย้อนกลับไปยังหน้ารายละเอียดรายวิชาก่อนหน้า
4. **ส่วนข้อมูลรายละเอียดผลงาน:** แสดงข้อมูลพื้นฐานของผลงานโครงงาน ประกอบด้วย ป้ายประเภทผลงาน (Web Application), ป้ายปี พ.ศ. (พ.ศ. 2569), ชื่อโครงงาน (ระบบจองห้องประชุมออนไลน์), รหัสรายวิชา (COM059), ประเภทผลงาน, ปีที่จัดทำ, ชื่อเจ้าของผลงาน (THIRAPAT WANGKEEREE), ชื่อรายวิชา (วิศวกรรมซอฟต์แวร์) และรายละเอียดผลงาน
5. **ส่วนแจ้งเตือนเข้าสู่ระบบเพื่อดูข้อมูลเพิ่มเติม:** แสดงข้อความแจ้งเตือน "เข้าสู่ระบบเพื่อดูข้อมูลเพิ่มเติม: กรุณาเข้าสู่ระบบด้วยบัญชีของคุณเพื่อดูไฟล์แนบ ลิงก์ผลงาน และร่วมแสดงความคิดเห็น" พร้อมปุ่ม "-> ไปหน้าเข้าสู่ระบบ"

---

#### 4.1.1.4 หน้าเข้าสู่ระบบ (Authentication & Login Page)

เมื่อผู้ใช้งานกดปุ่มเข้าสู่ระบบ ระบบจะนำทางมายังหน้าจอเข้าสู่ระบบ (`/login`) เพื่อให้ผู้ใช้ยืนยันตัวตนก่อนเข้าใช้งานระบบ

*(ภาพที่ 4.4 แสดงหน้าจอเข้าสู่ระบบ)*

จากภาพที่ 4.4 สามารถอธิบายส่วนประกอบของหน้าจอได้ดังนี้

1. **ปุ่มหน้าหลัก:** ปุ่มนำทางย้อนกลับไปยังหน้าแรกของระบบโดยไม่ต้องเข้าสู่ระบบ
2. **ปุ่มเข้าสู่ระบบด้วย Google:** ปุ่มสำหรับการเข้าสู่ระบบแบบ Single Sign-On ผ่านบัญชี Google
3. **ปุ่มเข้าสู่ระบบด้วย Microsoft:** ปุ่มสำหรับการเข้าสู่ระบบด้วยบัญชีอีเมลมหาวิทยาลัยพะเยา (@up.ac.th)
4. **ช่องกรอกข้อมูลเข้าสู่ระบบ:** ประกอบด้วย ช่องกรอกอีเมลหรือชื่อผู้ใช้งาน (Username) และช่องกรอกรหัสผ่าน พร้อมไอคอนรูปดวงตาสำหรับกดแสดงหรือซ่อนรหัสผ่าน
5. **ปุ่มเข้าสู่ระบบ:** ปุ่มกดเพื่อส่งข้อมูลไปตรวจสอบความถูกต้องและออกสิทธิ์การเข้าใช้งาน (JWT Token) ก่อนนำทางเข้าสู่ระบบ
6. **ลิงก์สมัครสมาชิก:** ลิงก์ "ยังไม่มีบัญชีผู้ใช้? สมัครสมาชิกที่นี่" สำหรับนำทางไปยังหน้าลงทะเบียนผู้ใช้งานใหม่

---

#### 4.1.1.5 หน้าลงทะเบียนผู้ใช้งานใหม่ (User Registration Page)

สำหรับผู้ใช้งานใหม่ที่ยังไม่มีบัญชีในระบบ สามารถกดเลือกลงทะเบียนจากหน้าเข้าสู่ระบบเพื่อมายังหน้าจอลงทะเบียน (`/register`) เพื่อสร้างบัญชีใหม่

*(ภาพที่ 4.5 แสดงหน้าจอลงทะเบียนผู้ใช้งานใหม่)*

จากภาพที่ 4.5 สามารถอธิบายส่วนประกอบของหน้าจอได้ดังนี้

1. **ปุ่มหน้าหลัก:** ปุ่มนำทางย้อนกลับไปยังหน้าแรกของระบบ
2. **ปุ่มสมัครด้วย Google:** ปุ่มสำหรับลงทะเบียนสมัครสมาชิกด้วยบัญชี Google
3. **ปุ่มสมัครด้วย Microsoft:** ปุ่มสำหรับลงทะเบียนสมัครสมาชิกด้วยบัญชีอีเมลมหาวิทยาลัยพะเยา (@up.ac.th)
4. **แบบฟอร์มกรอกข้อมูลสมัครสมาชิก:** ประกอบด้วย ช่องกรอกชื่อผู้ใช้งาน (3–30 ตัวอักษร ใช้ได้เฉพาะ a-z, A-Z, 0-9, ., _, -), ช่องกรอกอีเมล (@up.ac.th หรืออีเมลทั่วไป), ช่องกำหนดรหัสผ่าน และช่องกรอกยืนยันรหัสผ่าน พร้อมไอคอนรูปดวงตาสำหรับแสดงหรือซ่อนรหัสผ่าน
5. **ปุ่มสมัครสมาชิก:** ปุ่มกดส่งข้อมูลเพื่อบันทึกการสมัครสมาชิกใหม่ โดยระบบจะทำการเข้ารหัสผ่านด้วย Bcrypt และกำหนดสิทธิ์เริ่มต้นเป็นบุคคลทั่วไป (Guest)
6. **ลิงก์เข้าสู่ระบบ:** ลิงก์ "มีบัญชีผู้ใช้อยู่แล้ว? เข้าสู่ระบบที่นี่" สำหรับสลับกลับไปยังหน้าเข้าสู่ระบบสำหรับผู้ใช้ที่มีบัญชีอยู่ในระบบแล้ว

---

#### 4.1.1.6 หน้าแรกของระบบหลังเข้าสู่ระบบ (Home Page - Authenticated View)

เมื่อผู้ใช้งานเข้าสู่ระบบสำเร็จ ไม่ว่าจะเป็นผู้ดูแลระบบ อาจารย์ผู้สอน หรือนิสิต หน้าจอแรกจะปรับเปลี่ยนแถบเมนูและการแสดงผลตามสิทธิ์ของผู้ใช้งาน โดยแสดงเครื่องมือและเมนูการทำงานที่ได้รับอนุญาต

*(ภาพที่ 4.6 แสดงหน้าแรกของระบบหลังเข้าสู่ระบบ)*

จากภาพที่ 4.6 สามารถอธิบายส่วนประกอบของหน้าจอได้ดังนี้

1. **ส่วนข้อมูลผู้ใช้งานและปุ่มออกจากระบบ:** แสดงชื่อผู้ใช้งาน (`admin`), ป้ายแสดงระดับสิทธิ์ (`ผู้ดูแลระบบ`) และปุ่ม "ออกจากระบบ" สำหรับสิ้นสุดการทำงาน
2. **ส่วนแสดงสัญลักษณ์และชื่อระบบ:** แสดงตราสัญลักษณ์ UP พร้อมชื่อ "มหาวิทยาลัยพะเยา Classroom Hub" บนแถบเมนูด้านข้าง
3. **แถบเมนูนำทางหลักด้านข้าง (Sidebar Navigation):** แสดงรายการเมนูตามระดับสิทธิ์ของผู้ใช้งาน ประกอบด้วย:
   - *เมนูหลัก:* หน้าหลัก
   - *สำหรับผู้ใช้งาน:* เพิ่มผลงาน, จัดการผลงาน
   - *จัดการการเรียนการสอน:* เพิ่มรายวิชา, รายวิชาที่สอน, จัดการผู้ใช้งานในรายวิชา
   - *ผู้ดูแลระบบ:* จัดการผู้ใช้งาน
   พร้อมแถบแสดงข้อมูลและระดับสิทธิ์ผู้ใช้ที่ส่วนล่างของเมนู
4. **ช่องค้นหาอัจฉริยะ (Smart Search Box):** ช่องค้นหาแบบหน่วงเวลา (Debounce) รองรับการค้นหารายวิชา, ชื่อผลงาน, แท็ก และปี พ.ศ. แบบเรียลไทม์
5. **แท็บสลับมุมมองการกรองข้อมูล (Catalog Filter Tabs):** แถบปุ่มสำหรับกรองประเภทข้อมูล ได้แก่ "ทั้งหมด (25)", "รายวิชา (13)" และ "ผลงานที่มีผู้เข้าชมเยอะที่สุด (12)"
6. **การ์ดแสดงผลงานยอดนิยม (Popular Assignment Card):** การ์ดแสดงผลงานโครงงานยอดนิยม พร้อมข้อมูลประเภทผลงาน, ลำดับ, รหัสวิชา, ปี พ.ศ., ชื่อโครงงาน, รายละเอียดโดยย่อ และชื่อผู้จัดทำ

#### 4.1.1.7 หน้ารายละเอียดผลงาน การจัดการทรัพยากร และการแลกเปลี่ยนข้อเสนอแนะสองทิศทาง (Assignment Detail & Two-Way Feedback - Member View)

เมื่อสมาชิกในรายวิชาหรือผู้ดูแลระบบเปิดดูผลงานโครงงาน ระบบจะปลดล็อกการเข้าถึงไฟล์เอกสารโครงงาน การตรวจสอบสถานะลิงก์ภายนอก การติดตามรอบการทบทวนคุณภาพผลงาน และระบบแลกเปลี่ยนความคิดเห็นสองทิศทาง

*(ภาพที่ 4.7 แสดงหน้ารายละเอียดผลงาน การตรวจเช็คสถานะลิงก์ และระบบแลกเปลี่ยนความคิดเห็น)*

*(ภาพที่ 4.8 แสดงสถานะการดูแลรักษาทรัพยากรและการทบทวนคุณภาพผลงาน)*

จากภาพที่ 4.7 และภาพที่ 4.8 สามารถอธิบายส่วนประกอบของหน้าจอได้ดังนี้

1. **ส่วนข้อมูลผู้ใช้งานและปุ่มออกจากระบบ:** แสดงชื่อผู้ใช้ ป้ายบทบาท และปุ่มออกจากระบบที่มุมบนขวา
2. **ส่วนแสดงสัญลักษณ์และชื่อระบบ:** แสดงชื่อระบบบนแถบเมนูด้านข้าง
3. **แถบเมนูนำทางหลักด้านข้าง:** แถบเมนูด้านข้างตามระดับสิทธิ์ของผู้ใช้งาน
4. **ปุ่มย้อนกลับ:** ปุ่มสำหรับนำทางย้อนกลับไปยังหน้ารายละเอียดรายวิชาก่อนหน้า
5. **ปุ่มแก้ไขผลงาน:** ปุ่มสำหรับเข้าสู่โหมดแก้ไขข้อมูลผลงาน (แสดงเฉพาะเจ้าของผลงาน อาจารย์ผู้รับผิดชอบ หรือผู้ดูแลระบบ)
6. **ส่วนแลกเปลี่ยนความคิดเห็นสองทิศทาง (Two-Way Feedback):** แสดงจำนวนความคิดเห็นทั้งหมด รายการข้อเสนอแนะระหว่างอาจารย์และนิสิต พร้อมรูปโปรไฟล์ ชื่อผู้แสดงความคิดเห็น วันที่และเวลา และกล่องพิมพ์ข้อความสำหรับส่งข้อเสนอแนะ
7. **ส่วนข้อมูลรายละเอียดผลงาน:** แสดงข้อมูลสำคัญของผลงาน ได้แก่ ประเภทผลงาน, ปี พ.ศ. ที่จัดทำ, ชื่อผลงาน, รหัสรายวิชา, ชื่อเจ้าของผลงาน, ชื่อรายวิชา และคำอธิบายรายละเอียดผลงาน
8. **ปุ่มตรวจสอบสถานะลิงก์ (Link Health Check):** ปุ่มส่งคำร้องขอเพื่อทดสอบการเชื่อมต่อไปยังลิงก์ผลงานภายนอกแบบเรียลไทม์
9. **ส่วนรายการไฟล์แนบและปุ่มดาวน์โหลด:** แสดงชื่อไฟล์แนบ ป้ายสถานะการจัดเก็บถาวร (Permanent) และไอคอนปุ่มสำหรับดาวน์โหลดไฟล์เอกสาร
10. **ปุ่มเปิดลิงก์ผลงานภายนอก:** ปุ่มสำหรับเปิดลิงก์ผลงานภายนอก พร้อมป้ายแสดงสถานะสุขภาพของลิงก์ เช่น "พร้อมใช้งาน (HTTP 200)"
11. **กรอบสถานะการดูแลรักษาทรัพยากรผลงาน (Retention Lifecycle Tracker):** การ์ดแสดงสถานะการจัดเก็บถาวรของไฟล์แนบ, สถานะลิงก์ออนไลน์, จำนวนวันที่เหลือในรอบทบทวนคุณภาพประจำปี (365 วัน), วันครบกำหนดรอบดูแลถัดไป พร้อมปุ่มแก้ไข/อัปเดตทรัพยากรผลงาน และปุ่มตรวจสอบสถานะลิงก์

#### 4.1.1.8 หน้ารายละเอียดรายวิชาสำหรับอาจารย์ผู้สอนและผู้ดูแลระบบ (Class Detail Page - Teacher & Admin View)

เมื่ออาจารย์ผู้สอนประจำรายวิชาหรือผู้ดูแลระบบเข้าสู่หน้ารายละเอียดรายวิชา (`/class/:class_id`) ระบบจะแสดงเครื่องมือในการบริหารจัดการรายวิชา พร้อมป้ายแจ้งเตือนสถานะทรัพยากรผลงาน เพื่ออำนวยความสะดวกในการติดตามความสมบูรณ์ของโครงงานนิสิต

*(ภาพที่ 4.9 แสดงหน้ารายละเอียดรายวิชาสำหรับอาจารย์ผู้สอนและผู้ดูแลระบบ)*

จากภาพที่ 4.9 สามารถอธิบายส่วนประกอบของหน้าจอได้ดังนี้

1. **ส่วนข้อมูลผู้ใช้งานและปุ่มออกจากระบบ:** แสดงชื่อผู้ใช้ บทบาท และปุ่มออกจากระบบ
2. **ส่วนแสดงสัญลักษณ์และชื่อระบบ:** แสดงชื่อระบบบนแถบเมนูด้านข้าง
3. **แถบเมนูนำทางหลักด้านข้าง:** แถบเมนูด้านข้างที่แสดงเครื่องมือจัดการตามระดับสิทธิ์ของผู้ใช้
4. **ปุ่มกลับสู่หน้าหลัก:** ปุ่มนำทางย้อนกลับไปยังหน้าแรกของระบบ
5. **ส่วนข้อมูลรายวิชาและปุ่มแก้ไข:** แสดงรหัสวิชา, ปี พ.ศ., ชื่อรายวิชา, คำอธิบายรายวิชา และปุ่ม "แก้ไขรายวิชา" สำหรับอาจารย์เจ้าของวิชาหรือผู้ดูแลระบบ
6. **ปุ่มเพิ่มผลงานใหม่ (+ เพิ่มผลงาน):** ปุ่มสำหรับสร้างและส่งผลงานใหม่เข้ามายังรายวิชานี้โดยตรง
7. **รายการการ์ดผลงานในรายวิชาพร้อมป้ายแจ้งเตือนและปุ่มลบ:** แสดงผลงานในวิชา โดยมีป้ายเตือนสำหรับอาจารย์และแอดมิน เช่น "ไม่มีลิงก์" หรือ "ไม่มีไฟล์/ลิงก์" เพื่อติดตามงานนิสิตได้สะดวก พร้อมปุ่มไอคอนถังขยะสำหรับลบผลงาน (Soft Delete)

#### 4.1.1.9 หน้าสร้างและส่งผลงานใหม่ (Create Assignment Page)

สำหรับนิสิตที่ลงทะเบียนในรายวิชา อาจารย์ประจำวิชา หรือผู้ดูแลระบบ สามารถสร้างและส่งผลงานโครงงานเข้าสู่ระบบได้ผ่านแบบฟอร์มสร้างผลงานใหม่ (`/create-assignment`)

*(ภาพที่ 4.10 แสดงหน้าจอสร้างและส่งผลงานใหม่ ส่วนกรอกข้อมูลผลงาน)*

*(ภาพที่ 4.11 แสดงหน้าจอสร้างและส่งผลงานใหม่ ส่วนแนบไฟล์ ลิงก์ และปุ่มบันทึก)*

จากภาพที่ 4.10 และภาพที่ 4.11 สามารถอธิบายส่วนประกอบของหน้าจอได้ดังนี้

1. **ส่วนข้อมูลผู้ใช้งานและปุ่มออกจากระบบ:** แสดงชื่อผู้ใช้งาน บทบาท และปุ่มออกจากระบบ
2. **ส่วนแสดงสัญลักษณ์และชื่อระบบ:** แสดงชื่อระบบบนแถบเมนูด้านข้าง
3. **แถบเมนูนำทางหลักด้านข้าง:** แสดงแถบสถานะทำงาน (Active) อยู่ที่เมนู "เพิ่มผลงาน"
4. **ปุ่มกลับ:** ปุ่มสำหรับนำทางย้อนกลับไปยังหน้าก่อนหน้า
5. **แบบฟอร์มสร้างและส่งผลงานใหม่ (ส่วนข้อมูลพื้นฐาน):** ประกอบด้วย:
   - ดรอปดาวน์เลือกรายวิชา (* ข้อมูลจำเป็น)
   - ช่องกรอกชื่อผลงาน (* ข้อมูลจำเป็น)
   - ปุ่มเลือกประเภทผลงาน (Web, Application, Web Application, IOT, Document, Other)
   - กล่องข้อความกรอกรายละเอียดผลงาน แนวคิด หรือวิธีการใช้งาน พร้อมตัวนับจำนวนตัวอักษรคงเหลือ (จำกัด 500 ตัวอักษร)
6. **ส่วนแนบไฟล์และลิงก์ผลงาน:** ประกอบด้วย ปุ่ม "คลิกเพื่อเลือกไฟล์ (อัปโหลดได้หลายไฟล์)" รองรับไฟล์ PDF, Word, รูปภาพ, สไลด์ และช่องระบุ URL สำหรับแนบลิงก์ผลงานภายนอก (GitHub / Demo / Google Drive)
7. **ปุ่มดำเนินการ (Actions):** ประกอบด้วย ปุ่ม "ยกเลิก" สำหรับยกเลิกการทำรายการ และปุ่ม "สร้างผลงาน" สำหรับส่งข้อมูลและจัดเก็บไฟล์แนบเข้าสู่ระบบ

#### 4.1.1.10 หน้ารายการผลงานและการจัดการผลงาน (Assignment Management Page)

หน้ารวมผลงานที่นิสิตหรืออาจารย์เป็นผู้สร้าง และสำหรับผู้ดูแลระบบในการกำกับดูแลผลงานทั้งหมดในระบบ (`/assignments`) เพื่อความสะดวกในการติดตามสถานะผลงาน รอบการทบทวนคุณภาพ และการจัดการข้อมูล

6. **ช่องค้นหาผลงาน:** ช่องค้นหาจากชื่อผลงาน รหัสวิชา หรือชื่อผู้จัดทำ
7. **การ์ดแสดงรายการผลงาน:** แสดงรหัสวิชา, ผู้จัดทำ, ปี พ.ศ., สถานะจัดเก็บถาวร, ตัวติดตามรอบทบทวนคุณภาพผลงาน (ระบุจำนวนวันที่เหลือและวันครบกำหนด), ปุ่ม "ดูผลงาน", ปุ่ม "แก้ไข" สำหรับปรับปรุงข้อมูล และปุ่มไอคอนถังขยะสำหรับลบผลงาน

#### 4.1.1.14 หน้าจัดการผู้ใช้งานในระบบสำหรับผู้ดูแลระบบ (Admin User Management Page)

หน้าจอสำหรับผู้ดูแลระบบ (Admin) ในการกำกับดูแล ตรวจสอบสิทธิ์การเข้าใช้งาน กำหนดบทบาท และระงับการเข้าถึงของบัญชีผู้ใช้ทั้งหมดในระบบ (`/UserManagement`) ตามหลักการควบคุมการเข้าถึงตามบทบาท (Role-Based Access Control: RBAC)

*(ภาพที่ 4.17 แสดงหน้าจอจัดการผู้ใช้งานในระบบสำหรับผู้ดูแลระบบ)*

จากภาพที่ 4.17 สามารถอธิบายส่วนประกอบของหน้าจอได้ดังนี้

1. **ส่วนข้อมูลผู้ใช้งานและปุ่มออกจากระบบ:** แสดงชื่อผู้ใช้งาน (`admin`), ป้ายแสดงระดับสิทธิ์ (`ผู้ดูแลระบบ`) และปุ่ม "ออกจากระบบ"
2. **ส่วนแสดงสัญลักษณ์และชื่อระบบ:** แสดงชื่อ "มหาวิทยาลัยพะเยา Classroom Hub" บนแถบเมนูด้านข้าง
3. **แถบเมนูนำทางหลักด้านข้าง:** แสดงแถบสถานะทำงาน (Active) อยู่ที่เมนู "จัดการผู้ใช้งาน" ภายใต้หมวดหมู่ผู้ดูแลระบบ
4. **ช่องค้นหาผู้ใช้งาน (User Search):** ช่องพิมพ์ค้นหาผู้ใช้จากชื่อผู้ใช้ หรือรหัสประจำตัว เพื่อความสะดวกและรวดเร็วในการค้นหาบัญชีผู้ใช้
5. **ตารางแสดงรายชื่อผู้ใช้งานและการจัดการสิทธิ์ในระบบ (User Management Table):** แสดงรายชื่อบัญชีผู้ใช้ทั้งหมดในระบบ ประกอบด้วย:
   - *รหัสผู้ใช้งาน:* รหัสประจำตัวผู้ใช้ในระบบ เช่น `00001`, `69001`, `69002`
   - *ชื่อผู้ใช้:* แสดงชื่อบัญชี เช่น `admin (คุณ)`, `teacher`, `student01` พร้อมไอคอนรูปประจำตัว
   - *สิทธิ์การใช้งาน (Role):* ดรอปดาวน์สำหรับปรับเปลี่ยนระดับสิทธิ์ของผู้ใช้งานในระบบทันที (ผู้ดูแลระบบ, อาจารย์, นักเรียน, ผู้ใช้ทั่วไป) เพื่อควบคุมสิทธิ์การเข้าถึงข้อมูลและเมนูต่าง ๆ ในระบบ
   - *สถานะบัญชี:* แสดงไฟสถานะความพร้อมใช้งาน เช่น "ใช้งานปกติ"
   - *การจัดการ:* แสดงสถานะบัญชีปัจจุบัน หรือปุ่ม "ปิดใช้งาน" สำหรับระงับสิทธิ์การเข้าใช้งานระบบชั่วคราว

### 4.3.2 เกณฑ์การวิเคราะห์ข้อมูลทางสถิติและการแปลความหมาย

การประเมินใช้แบบสอบถามมาตราส่วนประมาณค่า 5 ระดับ (Likert Scale) โดยใช้สูตรทางสถิติในการวิเคราะห์ข้อมูล ได้แก่:

1. **ค่าเฉลี่ยเลขคณิต (Mean: $\bar{X}$):**
   $$\bar{X} = \frac{\sum X}{N}$$
   เมื่อ $\sum X$ แทน ผลรวมของคะแนนทั้งหมด และ $N$ แทน จำนวนผู้ตอบแบบสอบถามทั้งหมด (35 คน)

2. **ส่วนเบี่ยงเบนมาตรฐาน (Standard Deviation: S.D.):**
   $$\text{S.D.} = \sqrt{\frac{N\sum X^2 - (\sum X)^2}{N(N-1)}}$$

3. **เกณฑ์การแปลความหมายของค่าเฉลี่ย:**
   - **4.51 – 5.00** หมายถึง ระดับความพึงพอใจ / ประสิทธิภาพอยู่ในระดับ **มากที่สุด**
   - **3.51 – 4.50** หมายถึง ระดับความพึงพอใจ / ประสิทธิภาพอยู่ในระดับ **มาก**
   - **2.51 – 3.50** หมายถึง ระดับความพึงพอใจ / ประสิทธิภาพอยู่ในระดับ **ปานกลาง**
   - **1.51 – 2.50** หมายถึง ระดับความพึงพอใจ / ประสิทธิภาพอยู่ในระดับ **น้อย**
   - **1.00 – 1.50** หมายถึง ระดับความพึงพอใจ / ประสิทธิภาพอยู่ในระดับ **น้อยที่สุด**

### 4.3.5 สรุปข้อเสนอแนะเชิงคุณภาพจากผู้ใช้งาน (Qualitative Feedback)

จากการเก็บรวบรวมข้อเสนอแนะเพิ่มเติมในแบบสอบถามปลายเปิดของผู้ร่วมประเมิน สามารถสรุปประเด็นสำคัญได้ดังนี้:
1. **จุดเด่นของระบบ:**
   - การสืบค้นผลงานทำได้รวดเร็วและสะดวกมาก โดยเฉพาะการค้นหาด้วยปี พ.ศ. และระบบจำลอง Demo Login ช่วยให้ทดสอบระบบได้ง่าย
   - ระบบตรวจสอบสถานะลิงก์ภายนอกแบบเรียลไทม์ และป้ายเตือนผลงานที่ไม่มีไฟล์ ช่วยให้อาจารย์ผู้รับผิดชอบวิชาติดตามผลงานนิสิตได้สะดวกรวดเร็ว
   - การจัดเก็บไฟล์ถาวรพร้อมรอบทบทวนคุณภาพประจำปี ช่วยให้ผลงานโครงงานของสาขาวิชาไม่สูญหายเมื่อเวลาผ่านไป
2. **ข้อเสนอแนะสำหรับการพัฒนาเพิ่มเติมในอนาคต:**
   - ควรเพิ่มระบบแจ้งเตือนผ่านอีเมล (Email Notification) หรือ LINE Notify เมื่ออาจารย์หรือนิสิตเข้ามาแสดงความคิดเห็นในผลงาน
   - ควรเพิ่มระบบส่งออกรายงานสรุปสถิติผลงานประจำปีการศึกษาในรูปแบบไฟล์ Excel หรือ PDF เพื่อใช้ประกอบการประกันคุณภาพการศึกษา (AUN-QA)

## 4.4 บทสรุปของบท (Chapter Summary)

การทดลองและพัฒนา "ระบบคลังผลงานโครงงานและรายวิชา กรณีศึกษาสาขาวิศวกรรมคอมพิวเตอร์ มหาวิทยาลัยพะเยา" บรรลุผลสำเร็จตามวัตถุประสงค์ที่กำหนดไว้ทุกประการ:
1. **การพัฒนาระบบ:** ได้ระบบเว็บแอปพลิเคชันที่มีหน้าจอการทำงานครบถ้วน ทั้งโมดูลยืนยันตัวตน, จัดการรายวิชา, สมาชิกในวิชา, คลังผลงาน, การอัปโหลดไฟล์แนบหลายไฟล์รองรับภาษาไทย, การตรวจสอบความสมบูรณ์ของลิงก์ภายนอก, ระบบแลกเปลี่ยนข้อเสนอแนะ, และการจัดการสิทธิ์โดยแอดมิน รวมหน้าจอหลัก 14 หน้าจอ (17 ภาพแสดงผล)
2. **การทดสอบระบบ:** ผลการทดสอบกรณีทดสอบทั้ง 34 กรณีทดสอบ (Black-Box Testing และ RBAC Matrix Testing) พบว่าระบบทำงานผ่านเกณฑ์ทั้งหมด (**100% Pass**) ไม่พบข้อผิดพลาดที่กระทบต่อความปลอดภัยหรือความสมบูรณ์ของข้อมูล
